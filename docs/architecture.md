# 아키텍처

기능 단위로 코드를 모으는 모듈형 구조를 사용합니다. 현재 구현된 기능은 식단 수집과 조회입니다.

```text
src/
  app/                     Next.js 화면과 API 진입점
  components/
    theme-provider.tsx     시스템 테마 감지와 저장된 선택 복원
    theme-toggle.tsx       헤더의 라이트·다크 전환 버튼
  features/meals/
    types.ts               식단 모델, 저장소 인터페이스, 처리 결과
    date.ts                공통 날짜 검증
    calendar.ts            한국시간 오늘 날짜와 주간 날짜 계산
    presentation.ts        화면용 열량 집계와 표시
    components/            주간 날짜 선택과 끼니별 식단 화면
    import/                수집 순서와 적재 데이터 정리
    csv/                   국방부 요청, 다운로드, 디코딩, 파싱
    repositories/          Drizzle 기반 저장·조회 SQL
    http/                  HTTP 인증, 입력 검증, 응답 변환
    server.ts              실제 DB와 외부 데이터 소스를 연결하는 구성 지점
  lib/
    auth/                  카카오 인증 설정과 Cron 인증
    db/                    서버 전용 DB 연결과 스키마
```

API 경로는 `app/api`에 유지합니다. 경로 파일은 실행 환경을 선언하고 실제 의존성을 HTTP 처리 함수에 전달합니다. HTTP 함수가 DB 연결을 직접 만들지 않으므로, DB 설정 오류도 기존 JSON 오류 응답으로 처리됩니다.

수집 로직은 `ImportStore` 인터페이스와 전달받은 다운로드 함수를 사용합니다. 실제 저장소와 다운로드 구현은 `server.ts`에서 연결합니다. 저장소는 DB를 생성자 인자로 받아 숨겨진 연결 생성을 피합니다.

식단 타입은 Drizzle의 추론 타입에 의존하지 않습니다. DB 스키마가 식단 모듈의 끼니·상태 상수를 사용하므로, 처리 로직과 저장소의 값이 일치합니다. 수집 생략 사유는 코드로 전달하고, HTTP 응답에서는 내부 코드를 제외해 기존 응답 형식을 유지합니다.

공통 날짜 검증은 CSV 파서와 조회 파라미터 검증에서 사용합니다. 카카오 환경변수 검증은 인증 설정 함수 한 곳에서 수행합니다.

메인 화면은 Next.js Server Component로, `?date=YYYY-MM-DD`의 날짜를 검증한 뒤 하루 식단을 직접 조회합니다. 날짜를 생략하면 한국시간 오늘을 사용하고, 날짜 링크는 URL·새로고침·뒤로 가기에 선택 상태를 유지합니다. 하루 조회에는 목록 API의 페이지 제한을 적용하지 않습니다. 실제 데이터를 조회하지 못한 상태와 정상 조회 결과가 비어 있는 상태는 구분해서 표시합니다.

테마는 식단 기능과 분리한 공통 Client Component에서 관리합니다. `next-themes`가 시스템 설정 감지와 `menu-theme` 저장 값 복원, 탭 간 동기화를 처리하고, `globals.css`의 의미 기반 색상 토큰이 화면 전체에 적용됩니다. 사용자 선택이 없으면 시스템 설정을 따릅니다. 식단 조회와 화면의 나머지 부분은 Server Component로 유지합니다.

`npm run lint`는 수집·CSV·HTTP 코드에서 DB 구현과 서버 구성 지점을 직접 참조하는 것을 막습니다. 단위 테스트는 외부 DB나 네트워크 없이 실행하며, 저장소 인터페이스에 맞춘 가짜 구현을 사용합니다.

DB 스키마와 migration, 공개 API 주소는 이번 구조 정리에서 변경하지 않습니다. README는 환경 설정과 실행 안내만 유지합니다.
