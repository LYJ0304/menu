# 아키텍처

기능 단위로 코드를 모으는 모듈형 구조를 사용합니다. 현재 구현된 기능은 식단 수집·조회와 전역일 카운트다운입니다.

```text
src/
  app/                     Next.js 화면과 API 진입점
  components/
    main-navigation.tsx    식단표·카운트다운 메뉴와 현재 경로 표시
    theme-provider.tsx     시스템 테마 감지와 저장된 선택 복원
    theme-toggle.tsx       헤더의 라이트·다크 전환 버튼
  features/meals/
    types.ts               식단 모델, 저장소 인터페이스, 처리 결과
    date.ts                공통 날짜 검증
    calendar.ts            한국시간 오늘 날짜와 주간 날짜 계산
    presentation.ts        화면용 열량 집계와 표시
    components/            주간 날짜 선택과 끼니별 식단 화면
    import/                수집 순서와 적재 데이터 정리
    csv/                   국방부 요청, 다운로드, 디코딩, 파싱
    repositories/          Drizzle 기반 저장·조회 SQL
    http/                  HTTP 인증, 입력 검증, 응답 변환
    server.ts              실제 DB와 외부 데이터 소스를 연결하는 구성 지점
  features/military/
    countdown.ts           한국시간 날짜 검증, 남은 시간·D-day·복무율 계산
    use-military-countdown.ts  화면 생명주기에 맞춘 1초 시계와 구독 정리
    military-countdown.tsx  카운트다운 UI, 날짜 입력과 브라우저 저장
  lib/
    auth/                  카카오 인증 설정과 Cron 인증
    db/                    서버 전용 DB 연결과 스키마
```

API 경로는 `app/api`에 유지합니다. 경로 파일은 실행 환경을 선언하고 실제 의존성을 HTTP 처리 함수에 전달합니다. HTTP 함수가 DB 연결을 직접 만들지 않으므로, DB 설정 오류도 기존 JSON 오류 응답으로 처리됩니다.

수집 로직은 `ImportStore` 인터페이스와 전달받은 다운로드 함수를 사용합니다. 실제 저장소와 다운로드 구현은 `server.ts`에서 연결합니다. 저장소는 DB를 생성자 인자로 받아 숨겨진 연결 생성을 피합니다.

식단 타입은 Drizzle의 추론 타입에 의존하지 않습니다. DB 스키마가 식단 모듈의 끼니·상태 상수를 사용하므로, 처리 로직과 저장소의 값이 일치합니다. 수집 생략 사유는 코드로 전달하고, HTTP 응답에서는 내부 코드를 제외해 기존 응답 형식을 유지합니다.

공통 날짜 검증은 CSV 파서와 조회 파라미터 검증에서 사용합니다. 카카오 환경변수 검증은 인증 설정 함수 한 곳에서 수행합니다.

메인 화면은 Next.js Server Component로, `?date=YYYY-MM-DD`의 날짜를 검증한 뒤 하루 식단을 직접 조회합니다. 날짜를 생략하면 한국시간 오늘을 사용하되 19시부터는 다음 날 식단을 조회합니다. 기본 끼니는 00:00~08:29 아침, 08:30~12:59 점심, 13:00~18:59 저녁, 19:00부터 다음 날 아침입니다. 날짜 링크는 URL·새로고침·뒤로 가기에 선택 상태를 유지하고, ‘오늘’ 버튼은 시간과 관계없이 실제 오늘 날짜를 선택합니다. 하루 조회에는 목록 API의 페이지 제한을 적용하지 않습니다. 실제 데이터를 조회하지 못한 상태와 정상 조회 결과가 비어 있는 상태는 구분해서 표시합니다.

테마는 식단 기능과 분리한 공통 Client Component에서 관리합니다. `next-themes`가 시스템 설정 감지와 `menu-theme` 저장 값 복원, 탭 간 동기화를 처리하고, `globals.css`의 의미 기반 색상 토큰이 화면 전체에 적용됩니다. 사용자 선택이 없으면 시스템 설정을 따릅니다. 식단 조회와 화면의 나머지 부분은 Server Component로 유지합니다.

`npm run lint`는 수집·CSV·HTTP 코드에서 DB 구현과 서버 구성 지점을 직접 참조하는 것을 막습니다. 단위 테스트는 외부 DB나 네트워크 없이 실행하며, 저장소 인터페이스에 맞춘 가짜 구현을 사용합니다.

상단 메뉴에서 식단표(`/`)와 전역일 카운트다운(`/countdown`)으로 이동합니다. 현재 경로를 읽는 메뉴와 카운트다운을 Client Component로 분리하고 식단 조회는 Server Component로 유지합니다. 카운트다운은 전용 페이지에만 렌더링하여 식단표로 이동할 때 시계 구독도 해제합니다. 입력 날짜는 기존 날짜 검증을 재사용해 검사한 뒤 `menu-service-dates` 키로 localStorage에 저장합니다. 서버 렌더링에서는 브라우저 저장소나 현재 시각을 읽지 않으며, `useSyncExternalStore`가 hydration 이후 저장된 날짜와 시각을 반영합니다. 같은 탭의 변경과 다른 탭의 storage 이벤트를 구독하고 컴포넌트 제거 시 정리합니다.

카운트다운 시계는 1초마다 `Date.now()`를 읽어 계산하므로 지연이 누적되지 않습니다. 날짜가 없거나 잘못되면 시계 구독을 시작하지 않습니다. 탭이 숨겨지거나 pagehide 이벤트가 발생하면 타이머를 중단하고, visibilitychange·focus·pageshow 이벤트에서 즉시 재계산합니다. 화면 제거 시 타이머와 시계 이벤트 구독을 모두 정리합니다. fake timer와 고정 시각을 사용하는 Vitest 테스트가 날짜 경계와 시계 생명주기를 검증합니다.

DB 스키마와 migration, 공개 API 주소는 변경하지 않습니다.
